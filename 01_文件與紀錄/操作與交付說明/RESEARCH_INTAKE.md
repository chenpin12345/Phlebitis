# LINE 研究收件、授權與撤回

## 原則

- **分析用途與研究用途分開。** 病患傳照片只會得到分析結果；拒絕研究授權不影響分析。
- 照片只有在**明確、版本化的同意事件**之後才成為研究照片：正式 LINE 是經簽章驗證的 postback；模擬器是標示為模擬的事件。
- **模擬授權不等於真人研究授權。** 模擬來源一律標為 `test_only`（測試素材），正式訓練排除。
- 模型預測只作參考，與人工標籤分開保存，絕不自動成為標籤。
- 照片進入研究收件後，必須人工確認品質、標籤與個案關係，再**明確**轉入資料審查。轉入後仍需在資料審查核准，並通過任務資格檢查，才可能進入新的快照。

## 設定：`configs/research_consent.json`

| 欄位 | 說明 |
|---|---|
| `line_enabled` | 真實 LINE 是否詢問研究同意。**目前為 false**（專案負責人決定先以模擬器測試）。 |
| `simulator_enabled` | 模擬器是否詢問（可使用未核定草稿）。 |
| `current_version` / `versions` | 同意書文字、範圍、保存說明；`approved` 必須為 true 且 `line_enabled` 為 true，真實使用者才會被詢問。 |

**開啟正式同意前**：請由倫理審查（IRB）核定同意文字，新增版本並標記 `approved: true` 與 `approved_by`，再把 `line_enabled` 改為 true。

## 保存

依專案負責人決定，研究照片**保存至撤回為止，沒有自動到期**。這代表照片會長期留在本機 `runtime/workbench/research_intake/`；請依機構規範定期檢視是否仍符合研究計畫的保存期限。未同意的分析照片仍只暫存一小時。

## 流程

1. LINE 分析完成後，若同意功能開啟，回覆會另附「是否同意研究使用」的快速回覆（postback）。分析用的乾淨原圖（EXIF 已移除、無框無字）只在結果有效的一小時內暫存。
2. 使用者選「同意」：建立同意紀錄（來源、版本、範圍、時間、事件 ID、化名使用者鍵）與收件項目；照片複製到受控目錄。選「不同意」：只記錄決定；暫存照片到期刪除。
3. 照片已過期、已收回，或由其他使用者點選：明確回覆無法同意，要求重新傳送。重複的 webhook 事件與重複點選不會建立第二筆。
4. 研究人員在「LINE 研究收件」確認品質、二分類／分期、化名個案編號（需勾選已核對），再按「轉入資料審查」。相同內容已在資料集中時會拒絕，不會合併不同來源的個案身分；屬於獨立測試集的個案編號也會拒絕。
5. 轉入後的照片在資料審查中為「待審查」，依任務規則審查。

## 撤回

- 使用者在 LINE 傳「撤回研究同意」，或研究人員在收件頁按「記錄撤回」並填寫原因。
- **立即生效**：只寫入一筆簡短的資料庫交易（`usage_revocations`），不等待 GPU、資料鎖或檔案清理。資料查詢、快照建立、快照驗證與訓練前檢查都會立即排除。
- **實體清理**：排入可重試的背景工作（`cleanup_tasks`）。若運算或資料鎖忙碌，狀態會顯示「等待重試」與原因。清理會刪除研究照片副本、轉入的資料列與衍生副本，並把相關快照標記為已撤回。
- **已訓練的模型**無法因刪除照片而移除既有影響。系統會在模型版本上標記「需重新評估或重訓」，並保留歷史紀錄。
- 已撤回的照片不能透過垃圾桶「還原」重新取得授權。

## 垃圾桶

研究照片是垃圾桶的一種資源類型（`research_photo`）：

- 移入垃圾桶後隱藏，且不能轉入。
- 已轉入資料審查的項目會被阻擋，正式資料不直接從垃圾桶刪除。
- 永久刪除只移除照片副本，同意與稽核紀錄保留。

## 安全邊界

- 收件 API 只掛在本機工作台（127.0.0.1、CSRF、來源檢查），不在公開的 LINE 服務上。
- 照片讀取會檢查撤回與垃圾桶狀態。
- 日誌不記錄 token、userId 或照片內容；使用者鍵是以 Channel secret 產生的 HMAC。
