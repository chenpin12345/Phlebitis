## 6. 風險

| 風險 | 對策 |
|---|---|
| 改到一半中斷，程式和資料不一致 | 先寫暫存檔、留進度紀錄、一起生效 |
| `dedupe_key` 不一致，重複匯入多出證據 | 同一規則全部替換；規則重跑驗收 |
| 標籤紀錄被改壞卻沒發現 | 逐筆比對與反向還原檢查 |
| git 改寫時動到研究報告 | 依路徑排除，並比對這些檔案的雜湊 |
| 備份被動到 | 備份內容不改，只在驗收後移到待刪資料夾 |

**要先知道的代價**：標籤來源紀錄改完後，代號不再是當時實際用的文字。這是你決定的取捨，報告會寫明；實際對應關係只留在你刪除前的舊備份裡。
