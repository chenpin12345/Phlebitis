# Phlebitis 本地工作台：依現有程式碼修訂的實作 Prompt

請詳細閱讀現有 Phlebitis 專案，完成可運作的本地模型訓練、資料審查、模型評估及 LINE 模擬工作台。新增獨立的「模型與實驗」區，完整實作模型目錄、建立訓練實驗、追蹤訓練、比較結果、登錄與使用模型五項功能；支援下文指定的五個模型方案，訓練產物完成真實評估後必須顯示明確定義的準確率。先修正基礎流程，再依階段交付；所有階段都是本次範圍，不可只做介面或停在規劃。

## 1. 已知基線與工作邊界

- 現有基線固定 YOLO11n、單類別 phlebitis 物件偵測，不是疾病分類或嚴重度分級。本次明確擴充 YOLO11s、YOLO26s、EfficientNet-B0 與 DINOv2 ViT-S/14＋正則化線性分類器；保留 YOLO11n 作基準。偵測與影像分類是不同任務，不新增嚴重度分級，不把通用預訓練權重當成已訓練的靜脈炎模型。
- 現有 Python CLI 位於 src/__main__.py；資料、訓練、推論與 LINE 分別位於 src/data、src/training、src/inference、src/line_bot。已有 FastAPI、SQLite LINE 任務紀錄、OperationLock、Windows 啟動腳本。
- 截至本次審查：91 張圖片，24 張 approved（15 陽性、9 陰性）、62 張待審、5 張排除；24 張 approved 均未完成個案身分核對。請重新核對實際狀態，不將舊統計當成永遠正確。
- 已選模型的既有評估在 conf=0.5 時 TP=0、FN=4、FP=1、TN=2。這是該驗證折的紀錄，不是新病人的效能估計。工作台完成不代表模型具備實際病況判斷能力。
- 現有 18 項測試曾在本次審查通過。重新執行基準測試，補足新需求與失敗情境。
- 閱讀 AGENTS.md、README、相關程式、設定、測試、docs/HANDOVER.md、docs/TRAINING.md 及 docs/IMPLEMENTATION.md。確認差異後引用實際檔案說明，不得假裝已讀。
- 保留既有修改、原始資料、封存資料、實驗紀錄與 CLI；不要任意重寫整個專案、加入未列出的模型、熱像融合或臨床分級。新增候選模型不等於取代原有使用中模型；相依套件僅在新模型確有需要時調整，記錄並驗證相容性。
- 不傳送真實 LINE 訊息、不公開管理介面、不自行切換現有正式展示模型。不使用 archive/legacy 的舊程式作為執行入口。

## 2. 架構決策

採適合單機的模組化架構，沿用 Python/FastAPI；不要預設引入微服務、Redis、Celery、Kubernetes 或全套 MLOps 平台。前端選擇以維護成本和現有環境為依據。

分離以下責任：
1. 共用核心：圖片處理、推論、結果狀態、規則與回覆資料產生。
2. 管理工作台：資料、訓練、評估、模型與模擬 API。
3. LINE adapter：簽章、事件正規化、下載、回覆或推播與撤回。
4. 模擬 adapter：合成使用者、本地照片、假傳送器與可控制事件。
5. 計算工作管理：背景程序、排程、取消、狀態持久化與故障回收。
6. 模型 adapter／registry：描述模型任務、可用參數、預訓練權重、前處理、訓練／評估／預測／載入能力。YOLO 偵測、EfficientNet 分類及 DINOv2 特徵抽取加分類器各有實際實作，不把不同模型強塞進 YOLO runner。

區分三種物件：模型方案（例如 YOLO11s）、訓練實驗（一次特定資料與設定的執行）、模型版本（可載入的產物）。評估報告透過權重／分類器、前處理、門檻及資料快照雜湊綁定模型版本。共用工作排程、資料追溯與產物管理，保留各模型專屬的訓練與輸出語意。

管理工作台和 LINE 公開入口使用不同 app／port。HTTPS 通道只能連到 LINE 入口，不能因兩者同綁 127.0.0.1 就假設管理 API 不會被公開。管理端限制 Host／Origin，為有副作用的瀏覽器請求配置適當防護；不預設開放外網或跨來源存取。

第一版允許全機僅一個模型計算工作，明確顯示目前模式及資源占用。管理頁可一直開啟，但 LINE 推論工作程序啟動、停止與釋放模型須有明確生命週期。開始訓練若需要停止 LINE 接案，須明示影響、停止接新案、處理現有任務並釋放資源；不可默默讓病患訊息排隊到過期。不要只移除 GPU 鎖以達成並行。

本地模擬與 LINE 共用核心結果、事件規則與回覆產生器。對外訊息是由 adapter 映射的結構化資料；測試模式不得呼叫真實 LINE 傳送器。

## 3. 優先修正與回歸證據

先確認並修正下列目前程式中的問題；若已修正，提供證據：

### 3.1 逾時加通知失敗造成推論重疊
src/line_bot/service.py 的 work() 逾時分支先傳通知才等待仍在執行的 inference。通知失敗會跳過等待，下一件工作可能與上一條執行緒重疊。以假 predictor 延遲 0.2 秒、timeout=0.01、假 send() 丟例外、排入兩件工作，可重現最大同時推論數為 2。

不論傳訊成功、失敗或取消，未結束的計算都必須納入資源管理。補上「逾時＋通知失敗＋下一件工作」測試，驗證最大同時數符合資源政策。網路通知不可決定資源是否被正確釋放。

### 3.2 工作狀態與續訓
train() 的 resume 分支沒有和首次訓練相同的失敗狀態處理。建立 queued、running、cancelling、cancelled、failed、interrupted、succeeded 等明確狀態及允許轉移。

以獨立背景程序執行長時間訓練，持久化 job ID、程序身分、設定及生命週期；Windows 不可只依 PID 判斷程序歸屬。支援合作式停止、逾時後受控終止及重啟對帳。不能僅靠 FastAPI BackgroundTasks 或 request-local 執行緒承擔可續訓工作。

停止後只有已完成且可驗證的 checkpoint 可續訓。續訓和以權重開始新實驗分開；續訓鎖定原資料快照及必要參數，不將前端新設定假裝套用。可用框架 callback 收集結構化進度，避免只解析終端字串。各 adapter 應宣告續訓能力；不支援 checkpoint 續訓的線性分類 solver，顯示可重新執行及原因，不偽造續訓。

### 3.3 資料版本與人工審查
validate_split() 現在依賴整份即時 manifest 的 digest；連修改備註也會使舊資料集失效。改成「可變的審查目錄」與「不可變的實驗快照」分離。每個快照保存自己的圖片、框標註、分组、成員清單及雜湊，驗證快照本身，不依賴最新 manifest。

不得直接刪除既有完整性驗證。標註錯誤或身分核對變更時，保留歷史可追溯性並標記舊版本已撤銷／不適用；依資料刪除政策清除時明確標示歷史實驗不可完整重現，不偷換資料。

review() 的檔案搬移、標註更新、manifest 和審核紀錄不是同一交易。網頁加入並行請求前，提供單一寫入者或序列化機制、revision 衝突檢查與失敗復原。不要只靠原子寫入單一 CSV 宣稱整個流程安全。

### 3.4 評估與推論設定一致
evaluate() 目前寫死 imgsz=640、iou=0.7；Predictor 從全域 service.json 取設定。建立具型別與版本的推論設定，將影像處理、輸入尺寸、conf、NMS IoU、標籤及模型雜湊與評估結果綁定。

訓練尺寸與推論尺寸可以不同，但必須清楚記錄，啟用模型時採用已驗證的推論設定。AP 掃描門檻與使用情境的判斷門檻分開顯示。

### 3.5 模型切換
select() 目前依序覆寫 models/selected/best.pt、metadata.json、evaluation.json，程序中斷可能留下不相配檔案。改為不可變模型版本目錄，完整驗證後原子切換 active reference，失敗仍保留原模型可用。

本地測試模型與 LINE 模型引用分開。記錄切換及回復，避免單次請求混用版本。scripts/run_experiments.py 現在結束後會自動呼叫 select()；新的預設流程應只產生推薦結果，不自動更換 active 模型。

## 4. 資料集與矩形標註工作台

沿用 approved／pending_review／excluded 與 LabelMe→YOLO 的資料規則，提供：
- 圖片與原始標註預覽、矩形框新增／移動／縮放／刪除、正負樣本確認。
- 缺失標註、重複候選、來源與個案分組核對。
- 原始圖座標、顯示縮放座標與 EXIF 校正後座標的明確轉換；加入旋轉圖片的往返測試。
- 審查者、原因、revision、歷程及狀態管理。
- 資料快照、分割清單與雜湊驗證。

保留目前三折分組交叉驗證為可用預設。折數、種子及分割方式只能在群組與類別數量足夠時調整。未核對個案仍維持 demo 限制。不要在目前 24 張資料上強制切出看似正式的獨立測試集；提供預留／匯入真正獨立測試資料的機制與明確不足提示。

分類資料由同一資料快照中「經確認的 positive／negative 標籤」產生，保留相同 image_id 與分組；缺少框或標籤未知不等於陰性。偵測陽性圖片仍必須有有效框。若不同任務可用成員不同，顯示差異；跨任務比較只能採兩者皆合格的相同評估成員，且揭露訓練資料是否一致。分類前處理不得在評估時使用上線無法取得的真實病灶框裁切；記錄 resize／crop／padding 規則，避免默默裁掉目標。

## 5. 真正有效的訓練參數控制

各 adapter 從實際安裝的框架版本核對支援參數，建立個別 allowlist 與型別驗證，不把瀏覽器 JSON 任意展開成框架參數或 shell 命令。以下 YOLO 參數只適用於支援它們的偵測模型；分類模型採第 5.2 節設定。

基本設定：資料快照、fold、epochs、batch、imgsz、device、seed、patience。
進階設定依框架支援：optimizer、lr0、lrf、momentum、weight_decay、warmup、cos_lr、freeze、amp、workers、cache、deterministic、幾何／色彩增強、mosaic、mixup 及 box／cls／dfl 等適用 loss 權重。

已安裝框架在 optimizer=auto 時會忽略手動 lr0／momentum。介面應停用衝突欄位或要求改成手動 optimizer，並顯示「要求設定」與「實際有效設定」。不能在 YOLO 訓練介面用通用分類的 class weights、任意 loss 選單或虛構 gradient_accumulation 參數充當已支援功能；若以 nbs 等間接控制，須說明語意。YOLO26 的 loss、NMS／端到端模式必須按實際能力顯示，不機械沿用 YOLO11 的 dfl 或 iou 控制。

保留 YOLO 既有正規化與前處理契約，不提供會破壞預訓練輸入的任意選項。預設沿用現有可用設定；AMP 等選項若會觸發額外下載，須說明並避免默默更換模型。

提供參數用途、限制、匯入／匯出／模板、loss 與驗證曲線、epoch、耗時、可取得的 VRAM 資訊、日誌與 checkpoint 狀態。沒有測得的值顯示不可用，不虛構進度或剩餘時間。

### 5.1 模型區必須具備的五項功能

1. **模型目錄**：提供模型卡，顯示名稱、任務（框選／分類）、用途、輸出形式、所需標註、預訓練來源與版本、總參數及可訓練參數（能實測才顯示）、裝置與依賴需求，以及可執行／缺權重／缺依賴／不相容狀態。模型方案卡不填入未經本專案評估的「準確率」。使用者可進入該模型的實驗與產物列表。
2. **建立訓練實驗**：依序選模型方案、不可變資料版本、病患分組切分、訓練策略與參數。只顯示該方案支援的設定；送出前檢查類別數、群組、標註、裝置和參數衝突。支援儲存／複製設定，並區分新實驗與續訓。提供選取數個模型、共用指定 split 的比較實驗清單，執行前列出工作數與設定，預設依序執行，不自動遍歷大量參數。
3. **追蹤訓練**：顯示真實階段、進度、適用的曲線、有效參數、checkpoint、停止／取消／失敗原因。每次實驗獨立保存，不覆蓋舊模型。DINOv2 顯示特徵抽取完成張數及分類器擬合階段；solver 沒有逐 epoch callback 時不偽造訓練曲線。
4. **比較結果**：同資料、同分組及相容評估協定下比較準確率、漏報、誤報、定位品質及耗時。分類 accuracy 和偵測 mAP 分欄且不可互相排名；不同資料或門檻策略的結果標示不可直接比較。可查看同一圖片各模型的預測與真實標註、錯誤案例、各折結果並匯出報告，不自動宣稱最高 accuracy 的模型最好。
5. **登錄與使用模型**：訓練成功先保存為候選產物，背景排入綁定該產物的評估工作。評估成功才顯示可比較的數值；失敗時模型仍可追溯但標為評估失敗。選到 LINE 模擬器測試與啟用 LINE 使用中模型是不同操作。登錄、切換、回復遵守第 3.5 節；未評估模型只允許明確標示的開發測試，不誤標為已驗證。

### 5.2 必須實作的模型方案

| 方案 | 任務 | 初始训练策略 | 必須實作的能力 |
|---|---|---|---|
| YOLO11n | 單類別偵測 | 沿用既有預訓練微調作基準 | 保留既有訓練、評估、推論與相容性 |
| YOLO11s | 單類別偵測 | 預訓練微調，可設定受支援的凍結範圍 | 與 n 使用相同資料 split 的完整比較流程 |
| YOLO26s | 單類別偵測 | 官方預訓練權重微調 | 核對本機版本，記錄實際 loss 與推論路徑，不用 11s 或 n 代替 |
| EfficientNet-B0 | 二元影像分類 | 預設凍結主幹，只訓練分類頭 | 支援可選的有限層解凍微調，完整分類訓練與評估 |
| DINOv2 ViT-S/14＋正則化 logistic regression | 二元影像分類 | DINOv2 主幹固定且使用 eval 模式，只擬合分類器 | 特徵抽取、受控快取、分類器訓練、持久化、重新載入與推論 |

EfficientNet-B0 提供已實作的 learning rate、optimizer、weight decay、batch、epochs、early stopping、scheduler、增強、凍結範圍及適用類別權重。凍結主幹時同步處理 BatchNorm 等狀態，避免宣稱固定特徵但仍更新 running statistics。保存 backbone 權重版本、分類頭、前處理、label mapping、門檻與訓練設定。

DINOv2 使用固定、可追溯的官方小型預訓練變體及 pooling 規則。提供分類器支援的正則化強度、solver、max_iter、類別權重及特徵標準化；沒有實作的選項不顯示。標準化及任何 PCA／特徵選擇只能在當折訓練資料擬合，不能先用全部資料擬合。預設不增加 PCA 或高容量分類頭。特徵快取鍵包含輸入內容雜湊、預訓練權重、前處理及 pooling；快取視為衍生研究資料並遵守刪除政策。保存完整前處理與分類器 pipeline，重啟後可重現。

YOLO11m／l／x 與 DINOv2 全模型微調不在此次必要範圍。不得只把五個模型名稱列在 UI；五條路徑均需真正接通。缺依賴或權重時提供可恢復的準備流程並顯示限制，禁止用假分數或其他模型冒充。權重從官方可信來源下載至本地或由使用者提供，記錄來源、版本與雜湊；不得上傳病患圖片到雲端模型服務。支援離線使用已準備的權重。

### 5.3 過擬合、洩漏與比較公平性

- 顯示實際訓練／驗證圖片數、已確認個案数、分組核對狀態、凍結範圍及可訓練參數。不能只以模型大小判定過擬合。
- 預設採適合小資料的預訓練策略與保守增強；分類主幹凍結為初始策略，避免預設全面微調。early stopping 與 checkpoint 指標須記錄，不保證它能消除過擬合。
- 以一致的 eval 模式、無隨機增強的前處理比較訓練與驗證指標；訓練集數值只能標「訓練集擬合表現」。提供差距／趨勢提示及各折波動，不能自動貼上「沒有過擬合」保證。若做警示，其規則與門檻須透明。
- 保存所有實驗，不只保留最佳一次；預先設定比較模型與調參預算，無人要求時不執行大規模自動選模。揭露同一驗證集參與選模、選 checkpoint 或門檻調整，不將這些結果稱為獨立測試。
- 相同比較組共用病患群組及評估成員，記錄預訓練來源、解析度、有效 batch、訓練策略與資源预算。不同架構不強迫使用語意不相容的相同超參數；為各模型提供合理且有限的配置。
- 對跨個案、背景、取景、光線與標註差異保留案例檢查入口。資料增強不增加獨立個案數；多個 random seed 不能取代新個案。個案過少時明示結果僅供探索，不產生虛假的高精度信賴區間。

## 6. 模型準確率、偵測評估及結果語意

### 6.1 訓練產物必須顯示的準確率

「訓練完成」不等於已知準確率。每個產物顯示獨立評估狀態：待評估、評估中、成功、失敗、報告不適用。完成真實評估後，模型版本卡、實驗詳情與比較表必須顯示 **影像層級準確率 Accuracy = (TP + TN) / (TP + TN + FP + FN)**，以百分比和正確張數／有效評估張數一起呈現。不得把訓練集 accuracy、單張信心分數、框 precision 或 mAP 當成這個準確率。

例如：`驗證集影像準確率 75.0%（6/8 張；示範數值）`。示例僅說明格式，不能帶入實際 UI 當結果。標示分母與四捨五入規則，極小樣本不顯示誤導的小數位。

共同二元任務必須有固定標籤定義及判斷規則：
- 偵測模型：在指定後處理及 conf 下，至少一個合格的 phlebitis 框則預測 positive，否則 negative。明示這只衡量影像有無目標，不驗證框位置。
- 分類模型：依保存的 positive 類別分數、label mapping 與固定分類門檻轉成 positive／negative。分類門檻與 YOLO conf 不代表同一種量，不能強迫兩者數字一樣以宣稱公平。
- 品質拒絕、人工覆核、無法解碼及推論失敗不算正確，也不能默默丟掉。分開報告預先定義之有效樣本的基礎二元模型指標，以及啟用拒答／品質規則後的覆蓋率（有最終二元結果／全部輸入）、拒答數、失敗數和已回答樣本準確率。失敗或拒答不能硬塞成 negative；不同成功子集的 accuracy 不可直接排名，顯示缺失成員並使用相同預先定義成員的有效結果比較。

準確率旁至少一併顯示：
- TP／FN／FP／TN 混淆矩陣及陽性／陰性樣本數。
- 召回率／敏感度 TP/(TP+FN)、特異度 TN/(TN+FP)、正常圖誤報率 FP/(FP+TN)。
- Precision TP/(TP+FP)、F1，以及兩類均存在時的 balanced accuracy = (敏感度+特異度)/2。
- 資料快照／split／fold／成員清單雜湊、評估日期、門檻及推論設定、模型產物雜湊、程式版本（可取得時）。
- 評估用途：訓練集、驗證集、交叉驗證或獨立測試；demo_only 和個案分組是否已核對。

分母為零的指標顯示 N/A 與原因，不能顯示 0%／100% 代替；缺少任一類時不宣稱已完成兩類效能驗證。沒有可用的已標註評估資料時顯示「尚無可驗證準確率」，提供補標註／評估入口；不得用官方 COCO／ImageNet 分數、訓練 loss 或假資料補數值。

類別不平衡時仍依使用者要求顯示 accuracy，但同時顯示類別比例與多數類基準，避免只預測多數類就被列為最佳。訓練完成後預設評估所綁定的驗證 split；封存的獨立測試集不自動對每個候選反覆開封。

修改模型權重、前處理、門檻或評估資料，應產生新的版本化報告；舊報告保留但不再當成新配置的準確率。單張上傳頁面顯示該張預測分數與結果，不能宣稱單張「準確率」。

### 6.2 偵測專屬指標與交叉驗證

保留並區分：
1. 框層級：mAP50、mAP50–95、PR、匹配規則與漏框／錯框／定位偏差。
2. 影像層級：固定門檻下 TP／FN／FP／TN、召回與正常圖誤報率。

陰性圖片是空框標註，不是新增第二個 YOLO 類別。陽性圖上出現任意框不能代表定位正確。提供標註與預測疊圖、案例篩選、同資料快照模型比較及三折彙整；顯示樣本數，不只顯示百分比。不以比較不同 fold 的分數宣稱模型改善。

分類模型的 mAP／定位品質欄位顯示「不適用」，不能顯示零分。交叉驗證報告區分逐折指標、折平均與 out-of-fold 合併指標；合併時每個 image_id 在一輪分組交叉驗證只能出現一次且必須由未用該個案訓練的模型預測。多個 seed 的重複預測不可當成更多獨立樣本。各折模型的整體交叉驗證成績屬於實驗方案，不得貼成最後用全資料重訓模型已實測的準確率；後者需另有適當评估來源。門檻調整若使用同一驗證資料，清楚標明探索性選擇偏差；群組足夠時才採內外層評估。

### 6.3 結果 schema 與病患訊息

結果資料使用明確 schema 與狀態：suspected、not_detected、quality_rejected、needs_review，以及獨立的執行錯誤。messages.results() 目前將所有非 suspected 當成未偵測，必須改為完整狀態映射，未知狀態不得落成正常結果。

目前低於 conf 的候選框會被過濾。若要辨識低信心候選，需定義候選收集門檻、接受門檻與可追溯規則；沒有框不等於對陰性高度有信心。模型分數不可直接當疾病機率或嚴重度。

schema 額外記錄 task_type、model_id、model_version、preprocess_version、prediction_score／其語意與 decision_rule。分類輸出不偽造 boxes；使用 task_type 決定回覆，不因分類沒有 boxes 就顯示未偵測。若顯示解釋熱圖，必須獨立標示其用途且不可稱作已驗證病灶定位；熱圖不是此次必要功能。模型評估準確率屬於管理／研究資訊，不把它作為每次病患判斷的可信度。

## 7. LINE 模擬與除錯

提供繁體中文手機聊天介面：上傳照片、文字、處理中狀態、框選結果、Flex 支援子集、quick reply、多個合成使用者及重設。明確標示瀏覽器呈現近似，真實 LINE 客戶端仍需驗收。

模擬器可選取已準備的五種方案之本地訓練產物。偵測顯示框選，分類顯示整圖分類結果及分數語意；兩者皆維持研究展示、無法排除疾病與無嚴重度分級的界線。管理面板可查看模型的準確率與評估來源，但不把離線評估值顯示成該張照片的正確機率。

開發者面板顯示 trace ID、事件 ID、模型／資料／設定版本、輸入雜湊、各階段耗時、候選框與最終框、回覆 payload、錯誤碼；不顯示憑證或真實身分。

可重播文字、照片、重送、連續上傳、佇列已滿、撤回、撤回先於重送、模型缺失、下載失敗、推論逾時、通知失敗及 reply／push 選路。保存可控制的時鐘與必要事件狀態；不同 adapter 的 URL／token 等傳輸欄位可不同，共用核心語意須一致。傳送狀態與推論狀態分開，保留 delivery_unconfirmed 的可能性，不以盲目重試造成重複訊息。

## 8. 六項補強功能全部納入

### A. 照片品質與無法判斷
沿用解碼、格式、尺寸及像素上限，擴充可設定的模糊／曝光檢查、觸發原因及重新拍攝提示。未用代表性資料驗證前預設作提示，不冒充可靠排除規則。目標內容辨識沒有可靠能力時明示未支援。支援人工確認路徑，不強迫每張圖得出確定判斷。

### B. 錯誤回收與人工標註
收集誤判回報、低信心、品質問題及失敗案例，區分「待確認」與「已確認誤判」。支援矩形標註、備註、審核與納入新資料快照的歷程，不自動使用模型答案作真實標籤。

### C. 固定回歸案例
具版本的案例集保存輸入、預期結果或容許條件、對話狀態及基準設定。支援手動、新模型完成後及程式測試／CI 觸發。分開報告功能一致性、模型效能與耗時，列出改善、退步及錯誤。既有模型輸出只能作行為基準，不自動視為正確答案；模型效能案例須有人工標註。回歸案例不能取代獨立測試資料，不自動部署。

### D. 模型比較、切換與回復
實作本 prompt 第 3.5、第 5.1、第 5.2 與第 6 節，保留版本、權重／分類器雜湊、資料快照、設定及評估依據。模型卡顯示實測影像準確率與評估狀態。選定候選和啟用 LINE 模型是不同操作。

### E. 資料保護與操作紀錄
現有 LINE 承諾原圖不永久保存、框圖限時保存且不自動加入訓練。新增回收功能不得默默改成永久存圖。

預設保留既有模式；研究回收需有明確啟用與適用授權紀錄、用途及期限，且對使用者說明與实际行為一致。CLI／本地測試、LINE 暫存、研究資料、模型產物使用不同保存政策。撤回、到期清除與已授權研究副本的處置須明確定義，不能宣稱刪除一份就刪除所有副本。

研究編號與 LINE 對應資料分離；沒有需求不增加真實身分蒐集。限制圖片與身分映射存取，阻擋路徑穿越、任意命令及不受限上傳。模型檔案只能取自受控本地產物或受信任來源；不能將雜湊吻合當作可安全反序列化的證明。

記錄審核、匯出、刪除、訓練、設定變更及模型切換。單機未登入時標為本地操作者，不虛構帳號。日誌不含機密與不必要的病患資料。清理先提供預覽／dry run，限定受管理目錄，保護封存與仍被使用的產物；刪除資料後如破壞重現能力，須留下不含原圖的說明。

### F. 環境檢查與一鍵啟動
沿用 doctor、scripts/setup.ps1 與既有 CLI，新增 Windows 工作台啟動入口。檢查依賴、路徑、模型、GPU、空間、port 與工作程序；啟動失敗提供具體修正方式。安裝與日常啟動分開，不修改全域环境。無 LINE 憑證仍可開工作台與模擬器。GPU 不可用時在框架支援下提供明確 CPU 選項，不默默讓長任務退回 CPU。

## 9. 遷移與分階段驗收

依序完成，每階段有可執行結果與適當測試：
1. 建立基準、修正逾時併發及續訓失敗狀態，定義 schema 和設定契約。
2. 實作資料快照、審查寫入保護、模型不可變版本與原子 active reference；提供舊資料與模型的驗證／遷移工具，保留原始版本，失敗可復原。
3. 建立背景工作管理、資源模式與模型區五項功能，先跑通 YOLO11n／11s 的訓練、評估、準確率顯示與模型比較。
4. 加入 YOLO26s、EfficientNet-B0、DINOv2＋分類器的實際 adapter、訓練策略及個別產物驗證；不得以「架構預留」代替本次要求的功能。
5. 完成共用核心、五種模型產物的 LINE 模擬、回歸案例、錯誤回收、品質提示及資料生命週期。
6. 完成一鍵啟動、使用文件及整合驗收。

至少驗證：
- 原有 CLI 與 18 項測試繼續有效；若舊測試規定修改 live manifest 必須使快照失效，須隨新契約改寫並解釋，不保留矛盾需求。
- 不使用 GPU 的「推論逾時＋通知失敗」測試證實不重疊。
- 多次啟動／重複請求不會重複訓練；重整與服務重啟後工作狀態正確。
- 修改審查目錄不使完整歷史快照憑空失效；快照被篡改仍會拒絕。
- 並行標註衝突被偵測，寫入失敗可恢復。
- 前端要求設定、框架有效設定及評估／推論設定可追溯；auto optimizer 的衝突有測試。
- 模型切換途中故障仍可使用原模型，重新啟動不讀到混合版本。
- needs_review／quality_rejected 不會顯示為未偵測到疑似區域。
- 同一輸入經模擬與正式 adapter 的共用核心結果一致，撤回與重送規則有測試。
- LINE 公開入口不能存取管理 API、資料集、訓練控制或本地日誌。
- 五種模型方案都完成實際路徑的有限訓練／分類器擬合→產物保存→真實評估→準確率顯示→重新載入→模擬推論驗收；低 epochs 僅為流程 smoke test，明示不代表效能達標。限制工作量，採小 batch／有限 epoch／有限 solver iteration，不自動執行大規模調參、六組長實驗或切換既有 LINE 模型。環境、下載或資源受阻時逐一列出未驗證路徑、可重試指令和真實阻礙，不能以 mock 測試宣稱該模型已完成實訓。
- 使用已知 TP／FN／FP／TN 的測試案例核對 Accuracy、Recall、Specificity、Precision、F1、balanced accuracy 及四捨五入。涵蓋單一類別、沒有預測陽性、零有效樣本、拒答、推論失敗及缺少標籤。
- 測試未評估模型不顯示假準確率、分類模型不顯示 mAP、模型／門檻／資料變更不沿用舊分數、不同成員集合不直接排名。
- 測試分類標準化只使用訓練折、DINOv2 特徵快取按版本隔離、凍結策略及 label mapping 正確，分類沒有 boxes 時不被誤判為陰性。
- 測試各折指標与方案層級交叉驗證彙整的歸屬，不把 OOF 分數誤標為單一全資料重訓模型的已驗證準確率。
- 操作主要網頁流程，確認空白、載入、失敗與成功狀態；不只檢查編譯。
- 保存期限與刪除先用測試資料驗證，不動既有病患或封存資料。

最終交付修改摘要、檔案與架構、啟動方式、資料與參數操作、模型管理、模擬與回歸測試、保存政策、實際測試證據及剩餘限制。不得將合成資料測試視為模型效能驗證，或宣稱未執行的真實 LINE 串接已成功。
